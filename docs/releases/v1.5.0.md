# v1.5.0 — Smoother terminals, touch resizing, and local-first SSH

ComandOS v1.5.0 makes the desktop and remote terminal feel more immediate while
reducing avoidable background work. It also gives the public documentation a
precise local-first privacy model: state stays local by default, SSH uses direct
OpenSSH connections, and optional network integrations are documented instead
of hidden behind an absolute offline claim.

## Performance

- The tmux status hook now parses all current agent-state files with one bounded
  `jq` process instead of starting one process per file, while preserving its
  existing output and eight-hour cutoff.
- Concurrent dashboard `/state` cache misses now share one refresh, including a
  shared failure path, so bursts of clients do not repeat the same tmux work.
- Pane-model metadata is reconciled by one worker. Unchanged values produce no
  tmux or file writes, changed values converge to the latest generation, and
  stale pane metadata is cleared.
- Terminal input is still delivered immediately. This release does not batch
  keystrokes or add predictive local echo; it removes work around the input
  path instead.

## Resize and touch

- Desktop splitter drags cache their geometry, coalesce visual changes to one
  update per animation frame, and persist the final position once.
- Web-terminal fitting is frame-coalesced, and PTY dimensions are sent only
  when the row or column count actually changes.
- Remote one-finger gestures now have one owner: normal movement scrolls, while
  a deliberate long-press on a continuous tmux pane border enters resize mode.
- Border detection accounts for terminal scrollback, tolerates small transverse
  finger jitter, and rejects isolated `|` or `-` glyphs.
- Multi-touch, cancellation, disconnect, and frame teardown cleanly release any
  pending gesture or active resize.

## Remote interaction

- Web-terminal links now open their resolved URL through a direct, safe anchor
  activation with `noopener` and `noreferrer`. This fixes link clicks that could
  be blocked in Brave while preserving the same behavior in Chrome and other
  Chromium browsers; a blocked popup never replaces the embedded terminal.
- The ambiguous `🖱` control is gone. The single labelled **Select** / **Interact**
  control now reflects the real tmux mouse state after reloads, tab changes, and
  SSH sessions.
- **Select** disables tmux mouse handling for browser text selection;
  **Interact** enables it for terminal interaction and pane resizing. Temporary
  selection never silently enables mouse mode for an SSH session that started
  with it disabled.

## Local-first privacy

- Runtime data remains in local tmux sessions, local files, and local SQLite at
  `~/.claude/hooks/comandos-usage.sqlite`. ComandOS has no hosted ComandOS
  backend, external ComandOS database, telemetry service, or ComandOS SSH proxy.
- SSH hosts come from `~/.ssh/config`. Your installed OpenSSH client connects
  directly from your computer to the selected server; ComandOS does not upload
  your SSH configuration or private keys to a ComandOS service.
- If you explicitly request passwordless setup, `ssh-copy-id` copies only the
  selected public key to the server.
- AI provider traffic still goes to the provider selected by each CLI. Usage
  checks can contact Anthropic or OpenAI directly when corresponding credentials
  exist. Tailscale Serve, Telegram control, and Piper voice-model downloads are
  optional and use their respective services only when configured or requested.
- The ComandOS token gates the remote dashboard and cc-dash API. The optional
  interactive ttyd terminal has no separate ComandOS login and relies on your
  Tailscale access policy; both services bind only to loopback before Serve.
- Direct ttyd URLs no longer carry the dashboard control token in browser
  history, and `cc-webterm` no longer creates or reads that unrelated token.
- `cc-mobile off` now disables both the dashboard route on HTTPS 443 and the
  fallback terminal route on HTTPS 8443, tolerates an already-absent handler,
  and verifies that no ComandOS target remains without resetting unrelated
  Tailscale Serve configuration.

## Compatibility

- Existing tmux sessions, SSH configuration, local state files, HTTP clients,
  and the local SQLite schema remain compatible; no data migration is required.
- The remote dashboard and terminal continue to bind locally and can be exposed
  through the existing optional Tailscale Serve flow.
- Link activation is compatible with Brave and Chrome without weakening the
  dashboard preview sanitizer.

## Verification

The v1.5.0 release gate covers the Python regression suite, shell fixtures,
embedded JavaScript parsing, deterministic resize and touch harnesses,
concurrent state refreshes, pane-model reconciliation, tmux mouse-state
synchronization, and Brave-compatible terminal link activation. The final
release payload is also checked for whitespace errors and unrelated local
artifacts before publication.

## Upgrade

From an existing ComandOS checkout, run:

```bash
git pull --ff-only
./install.sh
systemctl --user restart cc-dash.service cc-notifyd.service
systemctl --user is-active --quiet cc-telegram.service &&
  systemctl --user restart cc-telegram.service || true
```

Then close and reopen the ComandOS desktop app so its embedded dashboard and
terminal assets are reloaded.
