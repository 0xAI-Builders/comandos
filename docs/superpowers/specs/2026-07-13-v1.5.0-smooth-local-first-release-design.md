# ComandOS v1.5.0 Smooth Local-First Release Design

## Objective

Ship ComandOS v1.5.0 as one verified, backward-compatible release that reduces
typing hitches and idle work, makes pane resizing responsive on desktop and
touch devices, removes the ambiguous remote mouse emoji, and presents the
project publicly as a local-first AI coding-agent terminal without making false
privacy claims.

All implementation, tests, documentation, and release metadata will land in
one final commit. No intermediate commits, tags, or partial GitHub updates are
allowed.

## Release scope

### Typing and resource usage

- Replace the per-state-file `jq` loop in `hooks/cc-status.sh` with one bounded
  `jq` process while preserving byte-for-byte output and the eight-hour cutoff.
- Make `/state` cache misses single-flight so concurrent callers share one
  `read_states()` result or the same failure.
- Keep pane model state in one backend cache. Write `@ccmodel` only when the
  value changes and clear stale values when a pane disappears or loses a model.
- Do not batch terminal input and do not add predictive local echo.

### Desktop and remote resizing

- Coalesce dashboard splitter updates to at most one visual update per animation
  frame, cache drag geometry at pointer-down, and persist the final value once
  on pointer-up or cancellation.
- Coalesce xterm fitting and PTY resize messages, sending dimensions only when
  rows or columns change.
- Replace the competing parent scroll listener and terminal resize listener with
  one explicit gesture arbitration contract: ordinary one-finger movement
  scrolls, while an engaged long-press on a verified tmux border resizes.
- Resolve visible terminal rows using `viewportY`, cancel pending or active
  resizing on multi-touch, `touchcancel`, disconnect, or frame teardown, and
  preserve the final exact SGR release.
- Validate a border by continuity instead of accepting an isolated `|` or `-`
  character as a pane border.
- Preserve the existing frame-coalesced SGR motion behavior.

### Browser-compatible terminal links

- Keep xterm.js link detection, but replace the bundled addon's two-step blank
  popup navigation with an explicit safe-link activation handler.
- Open the resolved `http` or `https` URL directly in a new tab with
  `noopener`, `noreferrer`, and no opener relationship so Brave and Chrome use
  the same user-gesture path.
- Preserve the current terminal session if a browser blocks a new tab; never
  navigate the embedded terminal frame away as a fallback.
- Do not weaken the dashboard preview sanitizer or turn untrusted agent text
  into unchecked HTML attributes.

### Remote mouse interaction

- Remove the `🖱` tab-bar control and its independent client-side state.
- Keep the `/tmux-mouse` backend capability.
- Use the existing labelled `Select` / `Interact` control as the only user-facing
  state machine.
- Expose the actual tmux mouse state to the client so reloads, SSH sessions, tab
  changes, desktop use, and remote use cannot disagree.
- `Interact` explicitly enables tmux mouse; `Select` explicitly disables it for
  browser text selection.

### Documentation, privacy, and SEO

- Keep `README.md` as the primary English README and retain the Spanish link.
- Change the hero title to identify ComandOS as a local-first mission control
  for AI coding agents.
- Mention Claude Code, OpenAI Codex CLI, Gemini CLI, OpenCode, tmux, SSH, and
  remote terminal/PWA naturally in the first section.
- Add a precise `Local-first by design` section explaining local storage,
  direct OpenSSH connections, and optional provider-specific integrations.
- Replace the inaccurate `No cloud, no DB` claim. ComandOS uses local SQLite,
  so the supported claim is: no ComandOS hosted backend, no external ComandOS
  database, no telemetry, and no ComandOS SSH proxy.
- State that SSH hosts come from `~/.ssh/config` and the installed OpenSSH
  client connects directly from the user's computer to the selected server.
  ComandOS does not upload SSH configuration, selected identity files, or
  private keys to a ComandOS service.
- Disclose optional network behavior: AI providers, Anthropic/OpenAI usage
  endpoints when credentials are available, Tailscale Serve, Telegram, and
  optional voice-model downloads.
- Distinguish the ComandOS token protecting the remote dashboard/API from the
  optional ttyd terminal, which has no separate ComandOS login and relies on
  the user's Tailscale access policy. Both services remain loopback-bound.
- Remove stale roadmap copy that describes already-supported agents as future
  work.
- Update the GitHub description and all 20 topics for relevant search terms.

The GitHub description will be:

> Local-first terminal mission control for Claude Code, OpenAI Codex CLI,
> Gemini CLI and OpenCode. Run AI coding agents in parallel tmux sessions,
> manage direct SSH connections, monitor usage and continue securely from phone
> via Tailscale. No ComandOS cloud, hosted database, telemetry or SSH proxy.

The GitHub topics will be:

`ai-agents`, `coding-agents`, `ai-coding`, `claude-code`, `codex`, `codex-cli`,
`gemini-cli`, `opencode`, `agent-orchestration`, `multi-agent`, `terminal`,
`tmux`, `ssh`, `ssh-client`, `local-first`, `privacy`, `self-hosted`,
`tailscale`, `developer-tools`, and `linux`.

## Explicitly excluded from v1.5.0

- Incremental JSONL importing with inode/offset tracking.
- Replacing polling with SSE or another event stream.
- Suspending, disconnecting, or destroying hidden remote terminals.
- Lazy restoration or LRU eviction of native VTE tabs.
- A full rewrite of tab identity, cwd, rename, or ordering synchronization.
- ttyd PAUSE/RESUME flow control.
- Adding a separate application-authentication layer in front of ttyd.

These changes require shadow comparison or extended soak testing and are
reserved for v1.6.0.

## Failure handling and compatibility

- Single-flight state refresh must wake every waiter on success or failure and
  must never leave the cache marked in-flight after an exception.
- A failed pane-model write must not fail `/usage/state`; successful cached
  values remain available for a later retry.
- Pointer and touch cancellation always flushes or cancels pending animation
  frames and restores iframe pointer events.
- Mouse-state reads and writes must reject invalid sessions through the existing
  session validation path.
- The HTTP API, tmux sessions, SSH configuration format, local state files, and
  local SQLite schema remain backward compatible.

## Verification gates

- Start from a green `pytest -q` baseline, correcting the stale snippets modal
  assertion before judging regressions.
- Prove `cc-status.sh` output equivalence with fixtures and a constant subprocess
  count independent of the number of state files.
- Prove eight concurrent expired `/state` requests invoke `read_states()` once,
  return identical data, and correctly share an injected exception.
- Prove unchanged pane models perform zero tmux writes and stale models are
  cleared.
- Exercise scroll and pane resize together with vertical and horizontal borders,
  1–3 px transverse jitter, scrollback, isolated glyphs, a second finger,
  `touchcancel`, and WebSocket closure.
- Prove 240 splitter moves produce at most one update per animation frame and one
  final storage write.
- Prove PTY dimensions are not sent twice when unchanged.
- Prove the remote UI contains no `🖱` control and that Select/Interact
  matches real tmux state after reload and for SSH sessions.
- Prove web-terminal links use a direct URL-bearing activation with
  `noopener`/`noreferrer`, without the Brave-sensitive blank-popup sequence.
- Parse all embedded JavaScript and run the complete Python/shell test suite.
- Run local GTK/VTE and remote Chromium touch smoke checks before publishing.
- Run `git diff --check` and confirm the final commit contains none of
  `.playwright-mcp/`, `json`, or `subprocess`.

## Publication

After all gates pass, create one final commit containing code, tests, README,
design, implementation plan, and release notes. Push that commit to `main`,
create annotated tag `v1.5.0`, push the tag, create the GitHub Release in
English, then update the repository description and topics. If any publication
step fails, stop without moving or recreating an already-published tag.

Release title:

> v1.5.0 — Smoother terminals, touch resizing, and local-first SSH

Upgrade instructions will use `git pull --ff-only`, rerun `./install.sh`,
restart the user services, and instruct users to restart the desktop app.
