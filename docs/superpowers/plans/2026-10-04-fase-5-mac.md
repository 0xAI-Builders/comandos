# Fase 5 — `comandos-app-mac` y broker del navegador en macmini: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** sustituir los dos componentes Python que viven del lado «Mac» —el broker MCP del navegador remoto (`services/browser/broker.py`, que corre en el host `macmini`) con sus clientes del portátil (`bin/cc-browser-remote`, `bin/cc-browser-expose`, `bin/cc-browser-npx-guard`, `lib/browser_config_migration.py`), y la app de escritorio macOS (`bin/cc-app-mac`, PyObjC + WKWebView + ttyd)— por binarios Rust con el mismo comportamiento, sin cortar ninguna conexión `chrome-bg` viva ni ninguna sesión, y con vuelta atrás de un solo comando.

**Architecture:** dos grupos independientes. **Grupo B (broker)**: un crate `comandos-browser` con la lógica del broker (protocolo MCP por líneas JSON, conjunto acotado de trabajadores Chrome, caducidad, cola, `status.json`) y el binario `comandos-broker-mac` que se compila aquí para `x86_64-unknown-linux-gnu` y se despliega en macmini en un puerto nuevo (19442) junto al Python (19441); los clientes del portátil pasan a ser subcomandos de `comandos browser …` despachados por `argv[0]`; el cutover es **por puerto**: las conexiones nuevas van al Rust, las abiertas siguen en el Python hasta que terminan solas (drenaje). **Grupo M (app)**: un crate de lógica pura compartida con la app GTK (`comandos-desktop`) y el crate `comandos-app-mac` (AppKit + WKWebView con `objc2`) que reproduce `cc-app-mac` cargando el tablero y la terminal de `comandos-term` desde `comandos dash`, sin ttyd; se empaqueta como `ComandOS.app`.

**Tech Stack:** Rust 1.96 (edition 2024), tokio 1.53.1 (`rt`, `net`, `io-util`, `process`, `sync`, `time`, `signal`, `macros`), serde_json del workspace (`arbitrary_precision` + `preserve_order`), `comandos_core::json::python::dumps` para la serialización estilo Python, `nix = "=0.31.3"` (señales), `sha2` del workspace; macOS: `objc2 = "=0.6.4"`, `objc2-foundation = "=0.3.2"`, `objc2-app-kit = "=0.3.2"`, `objc2-web-kit = "=0.3.2"`, `block2 = "=0.6.1"` (versiones leídas del índice local de cargo el 2026-10-04; `objc2-web-kit` no estaba en la caché: la Tarea M2 confirma la versión con `cargo update -p objc2-web-kit --precise 0.3.2 --dry-run` antes de fijarla).

**Spec:** `docs/superpowers/specs/2026-10-04-comandos-rust-complete-design.md` (§3.1 fila «`bin/cc-app-mac` y `services/browser/broker.py`», §4.1 binarios `comandos-app-mac` y `comandos-broker-mac`, §4.5 «macOS: `comandos-app-mac` con la misma interfaz y terminal», §5, §7 fila 5, §8 riesgo «macOS», Enmiendas 2, 3, 6 y 8). Documentación viva del servicio: `services/browser/README.md`, `docs/browser-config-migration.md`, `docs/browser-skill-routing.md`. Planes previos cuyos bloques **Interfaces** se consumen: `docs/superpowers/plans/2026-10-04-fase-3-term-y-web.md` (página de terminal servida por `comandos dash`, `xtask shots`/`png-diff`/`dom-diff`), `docs/superpowers/plans/2026-10-04-fase-4-app-gtk.md` (módulos puros de `comandos-app`: `state_files`, `ui/tabs` `TabRegistry`, `ipc`, `resume`, `restore`), `docs/superpowers/plans/2026-10-04-fase-2f-resto-del-tablero.md` (sub-plan 2f-1: registro de pestañas con dueño único).

**Precondición:** Fases 2 (todas), 3 y 4 fusionadas en `main` para el Grupo M. El Grupo B solo necesita la Fase 0/1 (`comandos install`, releases versionadas) y puede empezar ya. ## Hechos que condicionan el plan (leídos del repo el 2026-10-04)

1. **`macmini` corre Ubuntu 26.04 x86_64, no macOS.** `services/browser/README.md:3` («Chrome automation runs on the Mac mini (`macmini`, Ubuntu 26.04)»), `services/browser/runtime-manifest.json` (paquetes `_amd64`, `LD_LIBRARY_PATH …/x86_64-linux-gnu`) y el `comandos-browser.service` de systemd lo confirman. La spec (§4.1, §8) suponía que la app macOS se compilaría «en macmini por SSH»; con Linux allí eso no es posible: AppKit y WKWebView solo existen en macOS. Consecuencia: el Grupo B (broker) se hace y se verifica entero contra macmini; el Grupo M se escribe, se comprueba con `cargo check` para los dos objetivos Apple desde Linux y prueba su lógica pura en Linux, pero **ejecutarlo, empaquetarlo y firmarlo exige un host Darwin** (`MAC_HOST`). La Tarea 0 lo confirma y la aceptación de la fila 5 («funciona en la Mac») queda bloqueada hasta que Jesús designe ese host.
2. **El broker Python tiene un fallo de raíz conocido**: el 2-oct dejó de escribir `state/status.json` y no liberó sus dos plazas (`memory/oomd-mata-comandos.md`). Causa en el código: `housekeeping()` (broker.py:378) llama a `reap_idle()` → `release()` → `Worker.close()`, que lanza `RuntimeError('Browser descendants did not exit…')` (broker.py:155); la excepción mata la tarea de mantenimiento entera, sin registro, y desde ese momento nadie escribe el estado ni caduca trabajadores. La versión Rust nunca deja morir el bucle (Review Focus 1).
3. **Cada sesión de agente abre una conexión `chrome-bg` que dura lo que dura la sesión** (días): `cc-browser-remote` es el comando stdio del MCP y mantiene `ssh -W` abierto. Reiniciar el broker «closes its automation browsers and MCP connections» (README:55): cortaría la herramienta de navegador a todas las sesiones vivas. Por eso el cutover no reinicia nada: se abre un segundo puerto y se drena el primero.
4. **`cc-app-mac` no tiene ejecución verificable hoy en ninguna máquina de Jesús** (no hay host macOS conocido); su contrato es el código (`bin/cc-app-mac`, 1 348 líneas) y `tests/test_macos_app.py`.

## Decisiones del plan (no fijadas por el controlador)

- **D1 — `unsafe` en la frontera AppKit.** Propuesta: el crate `comandos-app-mac` no hereda la línea `unsafe_code` del workspace; declara `[lints.rust] unsafe_code = "deny"` y un único módulo `src/ffi/` con `#![allow(unsafe_code)]`, donde cada bloque `unsafe` lleva un comentario `// SEGURIDAD:` con el invariante y una prueba o una cita de la documentación de Apple. El resto del crate (estado, pestañas, menús como datos, URLs) es seguro y además vive en `comandos-desktop`, que hereda `forbid`. Alternativas descartadas: (a) `cacao` (API segura de AppKit) está sin mantenimiento y sobre `objc 0.2`; (b) un puente en Swift u Objective-C contradice «solo Rust». Si Jesús rechaza D1, el Grupo M se detiene tras M2 y se informa; el Grupo B no depende de esta decisión.
- **D2 — Cutover del broker por puerto, no por reinicio.** El Rust escucha en 19442; el cliente nuevo (`comandos browser remote`) lee el puerto de `~/.config/comandos/browser.json` (`{"host": "macmini", "port": 19442}`); sin archivo usa `macmini:19441`, el valor del script actual. Cada sesión nueva de agente lanza el cliente nuevo; las abiertas siguen con su `ssh -W` hacia 19441 hasta que terminan. Vuelta atrás: borrar el archivo (las sesiones siguientes vuelven al Python, que sigue escuchando hasta el final del drenaje).
- **D3 — Tope conjunto de trabajadores durante el drenaje.** Cada broker limita a 2 trabajadores Chrome; con los dos vivos el peor caso son 4. El Rust lee el `status.json` del Python (si tiene menos de 15 s) y cuenta sus `workers` dentro de su tope: no arranca un trabajador si `propios + python ≥ 2`. El Python no conoce al Rust, así que el peor caso solo baja a 3 si el Python crece después; se documenta y el controlador revisa `free -h` en macmini antes del cutover.
- **D4 — `start_new_session=True` → `process_group(0)`.** `setsid` desde Rust exige `pre_exec` (`unsafe`). `tokio::process::Command::process_group(0)` crea un grupo propio sin terminal de control, que es lo que importa bajo systemd (el broker no tiene terminal). La búsqueda de descendientes por `--user-data-dir` y por generación de PID (broker.py:22-59) se porta igual, así que la limpieza no depende del grupo.
- **D5 — Serialización.** El Python escribe mensajes con `json.dumps(m, separators=(',', ':'))` (ASCII escapado, compacto) y `status.json` con `json.dumps(status)` (separadores por omisión `', '` y `': '`). Se usa `comandos_core::json::python::dumps(value, true, true)` para los mensajes y `dumps(value, true, false)` para el estado. Los mensajes del trabajador se reenvían reserializados, igual que el Python (`json.loads` + `json.dumps`).
- **D6 — La app Mac habla con tmux, archivos y `comandos dash` como `cc-app-mac`**, con dos cambios: (a) la terminal ya no es `file://…/dash/term.html` contra ttyd (4779), sino la página de terminal de `comandos-term` servida por `comandos dash` (`{dash}/term.html?arg=…&theme=…&auth=…`, contrato que la Fase 3 conserva; si la Fase 3 lo cambia, `TermUrl::build` se adapta y lo anota); (b) las escrituras de `app-tabs.json` van bajo el `flock` de `app-tabs.json.lock` que usan `cc-dash` y la app GTK (`state_files` de la Fase 4). No se añade un modo remoto (app contra un tablero de otra máquina): `cc-app-mac` no lo tiene y la PWA lo cubre.
- **D7 — Pestañas: un `WKProcessPool` compartido y creación perezosa.** `cc-app-mac` crea un `WKWebView` por pestaña al restaurar. Con 20 pestañas eso son 20 procesos de contenido. La app Rust comparte un pool y crea el `WKWebView` de una pestaña la primera vez que se selecciona (las demás muestran solo su botón). Se mide RSS en la Tarea M6; si la creación perezosa cambia algún comportamiento observable (p. ej. el punto de estado), se corrige antes del cutover.
- **D8 — Firma.** Firma ad hoc (`codesign --force --sign - --options runtime`) por omisión: suficiente para correr la app en la Mac de Jesús. Developer ID y notarización solo si Jesús tiene cuenta de Apple Developer (pregunta en la Tarea 0); el paso existe en `xtask mac-bundle --sign <identidad>` pero no se ejecuta sin ese dato.
- **D9 — `comandos` en macOS.** La app necesita un `comandos dash` local en la Mac (como hoy el `cc-dash` Python por LaunchAgent). La Tarea M1 hace que el binario `comandos` compile para macOS con las piezas Linux tras `#[cfg(target_os = "linux")]` y equivalentes para macOS donde el Python también funciona en la Mac (procesos por `ps`, sin `systemd-run`, directorio de ejecución en `$TMPDIR`). Lo que en el Python ya está degradado en macOS (sin `/proc`) se degrada igual y se lista en `docs/verification/mac-degradations.md`.

// crates/comandos-browser/src/wire.rs
//! Mensajes MCP por líneas, con tope de 8 MiB como `asyncio.start_server(limit=MAX_MESSAGE + 1)`.
use serde_json::Value;
use tokio::io::{AsyncBufRead, AsyncBufReadExt};

pub const MAX_MESSAGE: usize = 8 * 1024 * 1024;

pub enum Line {
    Message(Vec<u8>),
    TooLarge,
    Eof,
}

/// Lee hasta `\n` sin acumular más de `MAX_MESSAGE + 1` bytes; si la línea es más larga
/// descarta el resto hasta el salto y devuelve `TooLarge` (el Python cierra la sesión).
pub async fn read_line<R: AsyncBufRead + Unpin>(r: &mut R, buf: &mut Vec<u8>) -> std::io::Result<Line> {
    buf.clear();
    let mut overflow = false;
    loop {
        let chunk = r.fill_buf().await?;
        if chunk.is_empty() {
            return Ok(if buf.is_empty() && !overflow { Line::Eof } else if overflow { Line::TooLarge } else { Line::Message(std::mem::take(buf)) });
        }
        let (take, done) = match chunk.iter().position(|b| *b == b'\n') {
            Some(i) => (i + 1, true),
            None => (chunk.len(), false),
        };
        if !overflow {
            let room = (MAX_MESSAGE + 1).saturating_sub(buf.len());
            let slice = chunk.get(..take.min(room)).unwrap_or_default();
            buf.extend_from_slice(slice);
            if take > room {
                overflow = true;
                buf.clear();
                buf.shrink_to(8192);
            }
        }
        r.consume(take);
        if done {
            return Ok(if overflow { Line::TooLarge } else { Line::Message(std::mem::take(buf)) });
        }
    }
}

pub fn encode_message(v: &Value) -> Result<Vec<u8>, String> {
    let mut s = comandos_core::json::python::dumps(v, true, true)?;
    s.push('\n');
    Ok(s.into_bytes())
}

pub fn encode_status(v: &Value) -> Result<String, String> {
    comandos_core::json::python::dumps(v, true, false)
}

    S: AsyncRead + AsyncWrite + Unpin + Send + 'static,
{

// crates/comandos-browser/src/broker.rs
async fn housekeeping(pool: Arc<Pool>, state_dir: PathBuf, mut stop: watch::Receiver<bool>) {
    let mut tick = tokio::time::interval(Duration::from_secs(5));
    tick.set_missed_tick_behavior(tokio::time::MissedTickBehavior::Delay);
    loop {
        tokio::select! {
            _ = tick.tick() => {}
            _ = stop.changed() => break,
        }
        // Un fallo de cierre nunca termina el bucle (2-oct: el Python dejó de escribir el estado).
        pool.reap_idle().await;
        pool.retry_stuck().await;
        if let Err(e) = write_status(&state_dir, &pool.status()) {
            eprintln!("comandos-broker-mac: no se pudo escribir status.json: {e}");
        }
    }
}

fn write_status(dir: &Path, status: &Value) -> Result<(), String> {
    use std::os::unix::fs::{OpenOptionsExt, PermissionsExt};
    let text = encode_status(status)?;
    let tmp = dir.join("status.json.tmp");
    let mut f = std::fs::OpenOptions::new().write(true).create(true).truncate(true).mode(0o600)
        .open(&tmp).map_err(|e| e.to_string())?;
    std::io::Write::write_all(&mut f, text.as_bytes()).map_err(|e| e.to_string())?;
    std::fs::set_permissions(&tmp, std::fs::Permissions::from_mode(0o600)).map_err(|e| e.to_string())?;
    std::fs::rename(&tmp, dir.join("status.json")).map_err(|e| e.to_string())
}

// crates/comandos-cli/src/browser/remote.rs
//! `cc-browser-remote`: pasa el MCP por `ssh -W` al broker de macmini (D2: puerto como dato).
use std::path::Path;

pub struct RemoteTarget {
    pub host: String,
    pub port: u16,
}

pub fn load_target(home: &Path) -> Result<RemoteTarget, String> {
    let path = home.join(".config/comandos/browser.json");
    let raw = match std::fs::read(&path) {
        Ok(raw) => raw,
        Err(e) if e.kind() == std::io::ErrorKind::NotFound => {
            return Ok(RemoteTarget { host: "macmini".into(), port: 19441 });
        }
        Err(e) => return Err(format!("no se pudo leer {}: {e}", path.display())),
    };
    let v = comandos_core::json::parse_slice(&raw).map_err(|e| format!("{} inválido: {e}", path.display()))?;
    let host = v.get("host").and_then(|h| h.as_str()).unwrap_or("macmini");
    let valid = !host.is_empty()
        && !host.starts_with('-')
        && host.bytes().all(|b| b.is_ascii_alphanumeric() || matches!(b, b'.' | b'_' | b'-'));
    if !valid {
        return Err(format!("host inválido en {}", path.display()));
    }
    let port = v.get("port").and_then(|p| p.as_u64()).and_then(|p| u16::try_from(p).ok()).filter(|p| *p >= 1)
        .ok_or_else(|| format!("puerto inválido en {}", path.display()))?;
    Ok(RemoteTarget { host: host.to_string(), port })
}

pub fn remote_argv(t: &RemoteTarget) -> Vec<String> {
    ["ssh", "-T", "-o", "BatchMode=yes", "-o", "ExitOnForwardFailure=yes", "-o", "ConnectTimeout=8", "-W"]
        .into_iter()
        .map(String::from)
        .chain([format!("127.0.0.1:{}", t.port), t.host.clone()])
        .collect()
}

pub fn run(home: &Path) -> i32 {
    use std::os::unix::process::CommandExt;
    let target = match load_target(home) {
        Ok(t) => t,
        Err(e) => {
            eprintln!("{e}");
            return 1;
        }
    };
    let argv = remote_argv(&target);
    let Some((program, rest)) = argv.split_first() else { return 127 };
    let err = std::process::Command::new(program).args(rest).exec();
    eprintln!("cc-browser-remote: no se pudo ejecutar ssh: {err}");
    127
}
